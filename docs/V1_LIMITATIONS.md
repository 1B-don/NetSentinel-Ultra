# Software RC1 limitations and release gates

RC1 is built and software-tested for Momentum Dev d3f89dfe/API 87.1/target 7. It is not a full hardware-verified v1.0 release. No new installation, launch, firmware operation or GitHub Release is authorized.

- Live ESP32 functionality is information-only. TX13/PB6, RX14/PB7, 115200/8N1 are owner-verified and SDK direction-checked. Connected means a completed, validated query with USART closed, not a persistent connection. Identity snapshots are volatile and explicitly historical; incomplete/mismatched replies are errors. Direct USB-C firmware/serial and previous queries are owner evidence, not new tests of this candidate.
- Wi-Fi parsing/analysis is implemented, but physical observation is blocked. The pinned-source recheck finds NULL/promiscuous discovery; the earlier hidden-AP initialization attribution was incorrect. Peer PCAP opens, SavePCAP defaults true, and installed passivity/privacy/cleanup remain unverified. Redacting Flipper logs cannot prevent ESP-side storage. Production transports remain info-only; protocol tests are host-only.
- BLE's reviewed discovery path uses active scanning and is excluded. No firmware change or guessed passive command is proposed.
- NRF24 physical SPI/CE/CSN routing, chip/capability detection and port ownership remain unverified. PRIM_RX with auto-ACK/retries/carrier/payload TX disabled is software-tested, not measured RF silence. RPD is threshold activity, not RSSI or decoded packets.
- CC1101 physical SPI/CS/GDO routes, installed external plugin identity, receive-only preset/autostates, recoverable bounded init/calibration and RSSI offset remain unverified. Public reference calibration can poll indefinitely and RX transitions can assert; an outer timeout cannot fix a blocking/fatal provider. RXOFF checking alone is not proof of passive initialization. Formal RF verification also needs a suitable signal source; its absence does not block the completed software core.
- The 60-second NRF/CC capture cap is checked by the worker before the next sample. It cannot interrupt opaque platform calls. The SDK five-byte UART TX, filesystem calls and mutex waits have no recoverable application deadline; protocol timeouts are bounded once control returns. Mock ownership and allocation checks do not independently prove ISR, GPIO, pin, heap or expansion-state restoration on hardware.
- Filters and diagnostics snapshots reset on launch; persistent NSP1 settings/history remain backward compatible. History retains the latest 16 sessions; existing CSV files are not deleted. Clock values are application-relative milliseconds, not wall time. CSV exports can leave reserved-ID gaps/partial files on errors, never overwrite prior files, and do not retain unique identifiers.
- Visual layout, final icon rendering, final menus/settings/history/exports, physical Back cancellation, repeated session soak and resource restoration require final artifact testing. Current official/matching SDK build evidence cannot replace those tests.
- Imported v0.2 redistribution licensing still needs the owner's explicit resolution before a public release; attribution is preserved in PROVENANCE.md. Source milestones are published only after tests/privacy review. Binaries/SDK/logs/captures remain local and ignored.

Smallest next action is to obtain the specific independently permitted documents in DEPENDENCY_REVIEW.md. For the presently supported GUI/storage/info feature set, the separate physical approval must name RC1's exact checksum and the procedure in V1_HARDWARE_VERIFICATION.md. Do not deploy unverified extra radios as part of that GUI/info test.
