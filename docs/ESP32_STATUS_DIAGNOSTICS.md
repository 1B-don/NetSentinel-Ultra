# ESP32 information-only status candidate

Baseline: `cdbddb38653d152dc3c62cd14c698bc00ea8d1e7`. Target: permitted Momentum d3f89dfe SDK, API 87.1, target 7. This candidate is software/SDK validated, not installed or physically tested. Earlier three successful information transactions and original-app interoperation remain evidence for the preserved earlier artifact only.

## Supported behavior

The existing dashboard's ESP32 Diagnostics screen now uses a typed query state independent of general UI/storage status: Disconnected, Connecting, Connected, Timeout, Protocol Error and Cancelled. Queued and active queries are Connecting; Connected means a complete, matched information transaction has ended and USART is closed. It does not mean a persistent connection or proof of ESP background RF silence. Serial/storage I/O failure closes USART and shows Disconnected with a separate result; malformed, incompatible or capacity-rejected replies show Protocol Error. Acquisition/configuration/storage failures before a query begins are reported separately. Unrelated settings/history outcomes cannot replace the latest information result.

Up/Down cycles four existing detail views: validated historical firmware/profile, IDF/SD snapshot, session/timing, and last information response outcome. The fourth view reports only complete/no-complete framed reply and the typed result. No raw “last response” bytes, identifiers, MACs or unknown fields are displayed or exported. Prior validated firmware/SD snapshots remain labelled last success after a failed or cancelled new attempt. Firmware constants are shown only after actual parser identity validation, never generated as live readings.

Only one exact `info\n` is allowed per acquisition. USART remains TX13/PB6, RX14/PB7, 115200 baud, 8N1, with SDK direction/baud checks before initialization. The serial controller rejects a competing owner; no forced release or logging/expansion/power change occurs. Back cancels queued or active info locally without sending a stop command. RX stop, serial deinit, buffer clearing and controller release precede context destruction.

## Actual protocol and limitations

Reviewed permitted public Marauder v1.11.0 commit `2ff3716e2307f8a1c3d2503936728b8cbc18acd8`: [CommandLine.cpp](https://github.com/justcallmekoko/ESP32Marauder/blob/2ff3716e2307f8a1c3d2503936728b8cbc18acd8/esp32_marauder/CommandLine.cpp) and [WiFiScan.cpp / RunInfo](https://github.com/justcallmekoko/ESP32Marauder/blob/2ff3716e2307f8a1c3d2503936728b8cbc18acd8/esp32_marauder/WiFiScan.cpp). Public files are retained only under ignored builds for review; no source was copied into the app. CLI reads LF-terminated input, trims it, echoes with `#`, dispatches plain info to RunInfo and prints `> ` afterward. Argument-bearing info can request AP details, so arguments remain denied. RunInfo emits identity/status plus unrelated free-RAM and MAC lines; only supported typed fields are accepted into diagnostics. It can change the ESP display mode; this is not a no-side-effects assertion for the peer firmware.

Accepted framing: `#info`, bounded lines with Firmware/Version/Hardware/ESP-IDF (or ESP-IDF Version), WSL Bypass, SD Card, SD Card Size and Battery Monitor, then `> `. Required target identity remains Marauder / v1.11.0 / Marauder v4 / v5.5.1-710-g8410210c9a. Enabled/disabled WSL and connected/non-connected SD variants are recognized; size/status consistency is checked. Other identities or incomplete/duplicate fields fail closed. Other board/battery profiles are unsupported, not guessed. The sanitized fixture is an invented reconstruction, not a retained owner capture; earlier physical Connected results do not independently validate every field or all framing assumptions.

The ISR ring, cumulative reply budget, worker batch limit, line capacity and wrapping response deadline remain bounded. Partial reads are supported. Serial errors/overflow poison the transaction; corrupt bytes are never repaired into a valid reply. Buffered bytes already present before dispatch are discarded. Fields/prompt before echo are ignored, and duplicate command echoes now fail rather than allowing reply merging. No command can restart from old queued input after Back.

Marauder info has no nonce/request ID. A complete delayed old reply arriving after a new command can have the same framing and identity; software cannot authenticate its freshness. The pre-dispatch snapshot cannot eliminate bytes arriving concurrently with or after it. This limitation remains explicit; no reset/help/flush command is added to overcome it. Real cancellation timing, absence of late peer output, field checks and pin/resource restoration remain pending separately approved physical tests.

The five-byte HAL TX call returns void and has no deadline/error status; existing short-command behavior is preserved. Parser deadlines/cancellation between worker calls do not preempt blocked firmware HAL calls. No whole-hardware-operation timing guarantee is inferred from host mocks or earlier successful transactions. Wi-Fi/BLE scanning, capture, help/stop/reset, firmware updates and every transmit-capable operation stay denied; NRF/CC remain disabled.
